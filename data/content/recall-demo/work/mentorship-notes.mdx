# 协作笔记

带新同事熟悉项目时，先给一页从本地启动、测试、发布到回滚的路径图，再安排一个小而完整的任务。问题最好以“现象、尝试过什么、下一步猜测”的格式提出，这比单独贴一段错误日志更容易得到及时帮助。

每周留出一次半小时回顾，记录哪些概念仍然模糊、哪些文档需要补充。代码评审先说明设计意图，再讨论实现细节；如果意见较大，就把决定写进 API 或发布记录。异步协作的目标是减少等待，而不是取消交流。
