# SQL 索引

这次复习重点是先看执行计划，再决定是否加索引。过滤条件、排序字段和连接键的组合比单独给每一列建索引更重要；索引顺序要符合常见查询的选择性。增加索引前记录查询耗时和写入成本，避免只为一个样例牺牲所有写入性能。

实际实验中，给事件表增加“租户、状态、创建时间”的联合索引后，最近列表扫描行数明显下降，但批量导入变慢了。以后每个索引都写清维护理由和删除条件，并把结果放进迭代复盘。学习时用间隔复习比一次读完整章更容易记住这些取舍。
