# API 决策

写入接口最终采用带业务幂等键的 upsert，而不是让客户端先查询再决定 insert 或 update。网络重试、移动端重复提交和队列重放都会让同一个请求到达多次；服务端根据租户与幂等键建立唯一约束，就能把重复写入收敛成一次结果。

响应中保留资源 ID、版本号和是否复用已有结果三个字段，便于调用方记录。数据库事务同时更新主记录和审计事件，失败时整体回滚。这个决定也会影响发布清单和事故复盘：迁移要先建立约束，监控要观察冲突率与超时率。
