# 迭代回顾

这次两周迭代按时完成了主要功能，但最后三天仍然集中处理集成问题。最有效的做法是每天上午先列出阻塞项，下午安排一次短同步；代码评审平均等待时间从一天降到了半天。下次希望把验收条件写进 issue，而不是等到发布前才补。

复盘时发现，事故记录、发布清单和 API 决策之间需要互相链接。新迭代开始时我会保留一个风险列表，每项写明负责人、监控信号和回滚动作。这样既能帮助团队协作，也能让下一次发布更容易从历史记录中找到依据。
